# Lab: The minimum batch job that will run 

Goals: 

1. Learn to use the COPY command in the ISPF Editor to insert lines into a member.
1. Set up a minimal job to execute IEFBR14.
2. Examine the spooler output files for a successful batch job.

## Step 1: Create a new member in your JCL library 

On the ISPF Edit panel, specify the data set name of your JCL library and the name of a nonexistent member, "MINIMUM". The Editor will open with blank lines available for you to enter text.

## Step 2: Copy the JOB statement from member JOB into member MINIMUM 

Instead of typing lines into member MINIMUM, copy the contents of member JOB into member MINIMUM. 

In the first column of the line of asterisks at the top of the Edit panel, type an "a" (for "after"). Position the cursor in the Command field and enter "COPY JOB". 

The contents of member JOB should now be replicated in member MINIMUM. 

When you are editing members in a library, you can specify the name of another member in the same library as the parameter for the COPY command. If you need to copy from a different library, you can specify that library's data set name and the member name in parentheses. If you omit apostrophes in the data set name, TSO will prepend the name with your TSO prefix. So...

- COPY JOB copies member JOB from the same library you're currently working in.
- COPY OTHER.LIBRARY(JOB) copies member JOB from <youruserid>.OTHER.LIBRARY.
- COPY 'USERID2.SOME.LIBRARY(JOB)' copies member job from USERID2.SOME.LIBRARY.

A common use for this is to save snippets of code that you use repeatedly in separate members, and use COPY to bring them into jobstreams or COBOL source files where you need them. It saves on typing and reduces the chances of making an error when entering code.

## Step 3: Change the jobname on the JOB statement

To give this job a unique name, change the trailing character on the jobname.

## Step 4: Add a step to execute IEFBR14

You will need an EXEC statement that specifies PGM=IEFBR14, and DD statements for SYSPRINT and SYSOUT, like this:

- //SYSPRINT DD SYSOUT=*
- //SYSOUT   DD SYSOUT=*

## Step 5: Locate the job output in SDSF 

Go to SDSF and locate your job output in either the Held or Output queue. This time, instead of typing an "s" (select) next to the entry, type a "?" (question mark) and then press Enter. 

SDSF will display a list of all the _spooler output data sets_ associated with this job run. There are three standard ones, which should be present because you coded MSGLEVEL=(1,1) on the JOB statement.

- JESJCL - The JCL after symbols have been resolved and JCL procedures have been expanded. This is the full JCL that JES2 processed when running the job.
- JESMSGLG - The JES2 message log. This shows messages generated by JES2 while it was processing the JCL.
- JESYSMSG - Messages pertaining to job and step processing, including data set disposition and any error codes that may have been produced. 

You can view one of these data sets by typing an "s" next to its entry in the list and pressing Enter. To exit from that view, press F3.

Browse through these data sets and see how much you can learn about how the job was processed. When you are working with more complicated JCL than this, there will be many more messages in these data sets.
